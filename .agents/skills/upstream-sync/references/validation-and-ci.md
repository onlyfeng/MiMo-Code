# 受影响验证与 CI 排错

同步入口和范围规则见 [SKILL.md](../SKILL.md)。本文件用于确定验证范围、处理当前 SHA 的失败；历史测试数量、超时值和 CI 分片不作为固定配置。

## 从能力追到既有消费者

先建立“输入变化 → 实现 → 调用者/存储/生成物 → 契约测试”的关系，再选择测试。除了上游新增或修改的测试，还要搜索 fork 已有的相关断言。没有文本冲突不代表没有语义影响。

| 变化 | 必须评估的既有契约 |
| --- | --- |
| SQL、持久化字段、事件投影 | 历史数据库升级、迁移 journal、导入/重放、重启幂等、并发写入；相关 prefix/checkpoint 测试 |
| HTTP/schema/工具参数 | 调用者、错误码、权限与目录准入、运行时 OpenAPI、已发布 SDK、旧夹具 |
| prompt/LLM/Actor 生命周期 | 请求身份、冻结工具与上下文、权限批准、持久化收据、取消/释放、inbox owner 与 follower |
| 配置、flag、模型路由 | 原始配置到实际解析对象的传递、优先级、默认路径和 opt-in 路径 |
| TUI 输入与异步状态 | 提交归属、迟到响应、删除后的读回、标题 locale、检查点和模型信息 |

这些是选择线索；具体 FD/FC/DC 边界仍以选定提交的注册表和实现为准。

## 分层证据

1. 先复现具体问题，再修正受影响契约。保持实际断言和权限边界。
2. 源码稳定后运行最终受影响矩阵；之后只因新修改、失败或未解决疑点补测。
3. 依赖使用 `bun ci`。测试和 `bun typecheck` 在所属 package 目录执行。
4. 默认路径按当前 AGENTS/owner 要求移除环境选择器，保留并报告 package preload。证明某功能默认关闭时，在选择器加载前已移除它的独立非测试进程中验证；测试 preload 的 opt-in 状态不能作此证明。
5. API 输入变化后从合并后的源码生成 SDK/OpenAPI；生成期间不要并发运行读取这些产物的检查。对两支输出分别验证，保留有依据的 compat API 扩展。
6. 区分静态检查、Bun 行为、真实 Node 行为、浏览器行为和可分发构建。只有用户要求本地二进制交付时，才按当前构建说明完成构建与启动验证；同步完成不等于本地客户端已升级。

矩阵记录文件/过滤条件、命令、SHA、环境、退出码、pass/fail/skip、过滤掉的数量和日志位置。`bun test -t` 使用正则：用无元字符的片段或正确转义；零匹配不是测试通过。并行累计耗时不是墙钟耗时。

共享文件完全相同且执行依赖、环境和目标运行时相同，才可说明复用先前证据的范围。文件相同不自动证明不同运行环境的行为；最终分支 SHA 的 CI 仍分别核验。

## 三类容易误修的失败

**迁移数量变化。** 固定历史 fixture 的截断点，确认真实 SQL 的执行集合与实际数据库效果。若实现正确而测试假定“只新增一条”，改为精确核对完整迁移身份集合，包括遗漏和重复；身份需使用完整迁移名称等真实唯一键，日期前缀不能区分同日迁移。不要只把 `+1` 改成另一个常数。保留旧字段/数据、原生 schema 和再次升级不变的断言。排序、去重或升级确有缺陷时应修实现。

**重复消息收据。** 先确认 fork 是否将消息和 part ID 都纳入身份检查。同一收据重试需稳定 ID；新消息不能复用旧 part ID。上游只检查标题不重复生成的测试，不证明消息入库幂等。适配夹具时增加数量/身份不变的验证，不放松生产一致性校验。

**断言通过但超时。** 区分夹具初始化、请求执行、取消和资源释放。用相同 SHA、环境和进程安排复现；必要时比较先前基线。仅有超时不足以判定偶发故障。若证实只是测试预算不足，可作有依据的、有上限的测试预算调整，保留断言和生产超时策略。不能用强制退出冒充生产关闭流程通过。

## 当前 SHA 的 CI 失败闭环

1. 从当前 workflow 读取触发分支、命令、分片、隔离任务和报告覆盖检查。确认失败 run 的完整 `headSha` 与目标一致；旧红灯单独记录。
2. 读取第一个实际失败及时间顺序。后续 fiber 中断或取消可能是连带结果，不能仅凭出现顺序断言因果。
3. 若单文件绿而 CI 合跑失败，保留 CI 的共享进程、文件集合/顺序、preload 和并发条件复现失败分片，再缩小组合。独立进程矩阵不能替代合跑验证。
4. 按已证实原因修生产实现、夹具或隔离设施。只有真实依赖/污染证据支持时才修改分片或隔离任务，并保留测试发现和报告覆盖检查；不得删除失败测试来通过同步。
5. 有基础设施或时序故障证据时，同一 SHA 至多重跑一次失败任务。重跑仍失败就保留失败状态并继续定位。服务不可用时记录阻碍和恢复条件，不循环重试或修改产品代码。
6. 修复及记录更新完成后，以新 SHA 重新发布和验证所有所需 CI。PR head 的绿灯、单文件复测绿灯、文档提交前的绿灯均不能替代最终分支提交的绿灯。

并行仅用于互不干扰的检查；共享 mock、配置、数据库、生成物或资源竞争存在时，选择有依据的隔离方式并记录限制。代理审查给出的结论只覆盖其实际读取的 SHA 和运行的验证。
