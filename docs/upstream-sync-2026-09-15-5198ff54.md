## Shared history preview correction discovered in compat review

PR #122 identified another C05 carrier of unbounded data: attachment metadata
was projected in full before the JavaScript response formatter applied its
budget. Because this is inherited behavior, the correction is owned by main
at `54deac139e638c4b72b6337cdaac0c27ad537749` and then propagated to compat.
The selected upstream baseline is unchanged.

Top-level filename, MIME and tool fields now use the existing 4,000 decoded-byte
preview guard. After removing data URLs, the entire attachment metadata array
is limited to 4,000 serialized bytes inside SQLite; an oversized list becomes
an array-shaped omission notice directing the caller to `history get part_id`.
Small metadata and NUL content retain their values. Raw stored parts, complete
get pages, original attachment locators and attachment delivery are unchanged.
This bounds SQL-to-JavaScript preview output, not SQLite's internal parse or
aggregation memory, raw get memory, or the total number of message parts.

Nine new real-database cases failed on the prior projection (59 pass, five
existing benchmark skips, nine failures) and pass with the correction. Final
`bun test test/history` is 68 pass, five benchmark skips, 0 fail and 612
assertions. Package typecheck and focused lint pass (four existing warnings,
0 errors), with the same default environment/preload policy as above. The
complete history suite avoids the existing isolated-import initialization
cycle; no preload or CI isolation policy changed.

Before this correction, accepted main `321e70c9` passed its exact-SHA
[test](https://github.com/onlyfeng/MiMo-Code/actions/runs/34879804908),
