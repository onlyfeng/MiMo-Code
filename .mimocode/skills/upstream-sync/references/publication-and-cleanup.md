# PR 收尾与工作树清理

本文件只处理用户已选择的发布或清理范围，不触发新的 upstream 同步。范围与冻结规则见 [SKILL.md](../SKILL.md)。不因技能存在而新增发布、消息发送或删除授权。

## PR 到最终分支

- GitHub 操作显式指向 `onlyfeng/MiMo-Code`。创建 PR 后核对 base repository；禁止向 upstream 推送或提 PR。
- 普通功能/修复从目标分支建分支并向目标分支提 PR；compat 自有工作走 feature → `dev/compat`。已授权同步的直接 main → compat 继承合并是例外。完整同步的 fork 推送属于同步请求；只请求输出技能或审计，不自动包含发布。
- 合并前读取实时 PR head/base、mergeability、所需 CI、reviewThreads、评论和后续提交。历史 `reviewDecision` 或“已解决”标签不是技术验证。
- 每条仍有关联的讨论核对当前代码：问题是否仍成立、由哪个提交修复、证据是否覆盖该路径。过时评论不自动失效；技术上已修但 UI 未解决，分别报告技术结论和流程状态。没有回复/解决讨论的授权时，不代发评论或更改讨论状态；满足已授权合并和仓库规则即可继续。
- 合并时使用刚审查的完整 head 作为并发保护。例如，仓库采用 merge 方式且已授权合并时：

```sh
gh pr merge "$pr_number" -R onlyfeng/MiMo-Code --merge --match-head-commit "$reviewed_head"
```

- head 从 H 变为 H2 时重读增量、讨论和 H2 的 CI，再作决定；不要仅重试合并命令。合并方式遵循仓库及用户约定，不强制套用示例的 `--merge`。
- 合并后记录实际 merge SHA，并验证落地分支该 SHA 的 CI；按授权范围传播 compat。刷新允许刷新的 refs，检查远端 tip 和祖先/排除关系。文档/注册表更改同样使最终 SHA 改变，必须放在最终 CI 证明之前。
- 共享 FD/FC 记录由 main 维护，compat 继承相同内容；compat 专属登记保留在自己的注册表。源码/测试、共享指导内容、纯记录提交分别指向其真实快照。

## 两种清理入口

| 用户范围 | 可清理对象 |
| --- | --- |
| 普通同步收尾 | 本次创建、已记录、没有用户工作且已经集成的临时分支/工作树；只读审计工作树无须合入 |
| 同步之外、用户点名要求移除旧工作树 | 仅限该请求逐个点名的旧资源，即使不是本次创建；重新核对状态并处理未提交内容后执行，不重复索要已经给出的授权 |

第二行只对同步之外的独立请求生效，且只覆盖该请求逐个点名的对象；没有这种点名授权时第二行不存在。同步收尾一律走第一行：不是本次创建、未记录、带用户工作或脏的工作树全部保留并报告，`AGENTS.md` 的“保留无关或脏工作树”在此不放宽。

“看看是否可以删除”只授权评估，不等于删除；“全部移除”只覆盖上下文已明确列出的对象，不扩展到其他项目、主工作区或备份。受保护分支、开放 PR 或活跃写入者有未解决归属时，保留该对象并说明具体阻碍。

## 可恢复清理顺序

1. **锁定对象。** 记录完整路径、工作区管理器 ID、分支、HEAD、索引/工作区修改、未跟踪文件、相关 PR 和已集成证据。查看忽略文件，区分可重建依赖与需要保留的数据。分支名相似、CI 绿或树差异为空均不能代替提交集成证明。
2. **核对工作是否仍独有。** 以祖先关系判断已提交内容；squash/cherry-pick 无祖先关系时，用实际补丁和当前行为证据核对。对脏草稿按能力比较，不将原 HEAD 已合入当作未提交内容也已合入。
3. **保存未提交内容。** 除非用户明确要求丢弃，先在删除范围之外保存基准 SHA、binary 工作区补丁、索引补丁、未跟踪文件及需要保留的忽略文件。记录删除、重命名、文件权限和符号链接。备份采用受限权限，不将凭据或个人路径写进仓库文档；列明排除的可重建依赖。
4. **验证可恢复。** 检查备份清单/哈希，并确保删除分支后基准提交仍由保留分支可达；否则先将必要提交保存到可验证的独立 Git bundle 等持久备份。仅记录 SHA 或仅在删除前确认对象存在，不保证垃圾回收后可恢复。在隔离 checkout 或临时 index 检查补丁适用性，包含二进制、未跟踪和符号链接的恢复检查。清理前重新比较状态与备份快照；若有新增写入，更新备份或保留工作树，不能继续使用旧快照。
5. **通过归属系统移除。** Paseo 管理的工作树，先使用可用的 workspace 工具核对归属，再归档用户授权的 workspace；它可能一并关闭其代理/终端并删除最后引用的工作树。工具不可用时先查当前 CLI 帮助；不要为清理擅自重启 daemon。普通 Git 工作树使用 `git worktree remove`。脏工作树仅在该对象已被用户点名授权移除、且备份与恢复验证均满足后才考虑强制移除，不用宽泛目录删除替代归属检查。
6. **删除指定分支。** 确认没有工作树再使用它，且提交可从保留的分支或备份恢复，再删除对应临时分支/引用。优先非强制删除；特殊集成方式需要独立等价性证明。不要自动删除远端分支，除非其也在授权清理范围。
7. **独立验收。** Git 工作树记录、实际目录、分支引用以及可访问的管理器工作区记录分别核对；主工作区状态和无关资源应保持不变。报告备份位置和保留项，目录删除不等于管理器记录已归档。

若清理期间另一个操作者已归档或删除目标，重新核对实际状态及剩余引用，完成尚未完成的步骤。不要把已消失的目录当作新建空目录的理由，也不要声称自己执行了已由他人完成的归档。
